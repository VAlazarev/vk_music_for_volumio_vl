# VK Music for Volumio

Плагин VK Музыки для Volumio — источник музыки (`music_service`) по образцу
[yandex_music_for_volumio](https://github.com/VAlazarev/yandex_music_for_volumio).

> **Статус: каркас.** Настройки, авторизация и корень каталога написаны;
> навигация по разделам и воспроизведение — нет. См. «Что дальше».

## Как это работает

Публичный audio API VK закрыт для сторонних приложений с 2016 года, поэтому
плагин обращается к тем же приватным эндпоинтам, что и веб-плеер:

| | |
|---|---|
| API | `https://api.vk.ru/method/`, версия `5.282` |
| Авторизация | cookie `p` + `remixsid` → access token через `https://login.vk.ru/?act=web_token` |
| Каталог | `catalog.getAudio`, `catalog.getSection` |
| Поиск | `audio.search`, `audio.getSearchSuggestions` |
| Лайк / снятие | `audio.add` / `audio.delete` |

Форма ответов разобрана по исходникам [`@toil/vk-audio`](https://github.com/ilyhalight/vk-audio)
(MIT). Сама библиотека не используется — она собрана под Bun и ESM, а плагину
нужен CommonJS под Node внутри Volumio, поэтому нужные вызовы переписаны
напрямую в [`vk.js`](vk.js).

### Авторизация

Официального способа получить токен нет. Рабочий путь — забрать из браузера два
cookie, и они лежат **на разных доменах**: `remixsid` на `vk.ru`, а `p` на
`login.vk.ru`. В DevTools → Application → Cookies это две отдельные записи, и
на `vk.ru` никакого `p` нет — на этом легко споткнуться. Оба обязательны: с
одним `remixsid` обмен на токен отвечает `unauthorized`.

Cookie живут 50+ дней, а вот access token из них — всего ~15 минут, поэтому
плагин обновляет его сам.

Пароль VK при этом никуда вводить не нужно. Cookie хранятся в конфиге плагина
на устройстве (`/data/configuration/music_service/vk_music/config.json`) и в
репозиторий не попадают — в `config.json` здесь лежат только пустые заготовки.

### Как проигрывать — вопрос закрыт: нужен прокси

Проверено на живом аккаунте 26.09.2026 (`tools/probe.js` + разбор плейлиста).
Прямого mp3 больше нет, **нужен прокси**. Что именно отдаёт VK:

Ссылка на трек имеет вид, под который не подходит ни один из известных
шаблонов переписывания — ни `/pNN/`, ни `/audios/`, а один непрозрачный
подписанный сегмент:

```
https://cs9-18v4.vkuseraudio.ru/s/v1/ac/<подписанный токен>/index.m3u8?siren=1
```

Попытки достать файл напрямую дают 404: `<token>.mp3`, `<token>/index.mp3`,
`<token>.m4a`. Поэтому `m3u8ToMp3()` оставлен как есть — он корректно не
трогает нераспознанный формат, — но рассчитывать на него нельзя.

Сам плейлист — обычный VOD HLS, 16 сегментов на трек в 284 секунды,
`EXT-X-TARGETDURATION:20`. Главная особенность: **шифрование чередуется**.

```
#EXT-X-KEY:METHOD=AES-128,URI=".../key.pub?siren=1"
#EXTINF:1.984,
seg-00-a2.ts?siren=1
#EXT-X-KEY:METHOD=NONE
#EXTINF:3.994,
seg-01-a2.ts?siren=1
#EXTINF:19.997,
seg-02-a2.ts?siren=1
#EXT-X-KEY:METHOD=AES-128,URI=".../key.pub?siren=1"
...
```

То есть примерно каждый третий сегмент зашифрован AES-128, остальные идут
открытым текстом. Ключ лежит по `<база>/key.pub?siren=1`, отдаётся как 16 байт
`application/octet-stream`. Первый сегмент — 84 608 байт, начинается не с
`0x47`, потому что он как раз зашифрован.

Существенно: **медиа-ссылки не требуют cookie или токена** — подпись в пути
авторизует сама себя. Прокси не придётся пробрасывать авторизацию на CDN.

#### ffmpeg сам с этим не справляется

Проверено на устройстве (Volumio, ffmpeg 5.1.8, Raspberry Pi 4). Наивное
`ffmpeg -i <m3u8> -c:a copy -f mp3` **молча теряет треть трека**: на 284
секундах выдаёт 186. В подробном логе видно, что ffmpeg честно забирает ключ и
открывает сегмент через `crypto+https://`, но получает
`Invalid data found when processing input` и выбрасывает все зашифрованные
сегменты. 284 − 186 = 98 секунд, что в точности равно суммарной длительности
шести AES-сегментов.

При этом шифрование совершенно обычное. Ручная проверка: `AES-128-CBC`, ключ
16 байт из `key.pub`, IV — номер сегмента (для нулевого сегмента это нули),
на выходе валидный MPEG-TS с сигнатурой `0x47` и пакетами по 188 байт, то есть
байт в байт та же структура, что у незашифрованных сегментов. Плюс PKCS#7
padding: 84 608 байт шифротекста дают 84 600 = 450 × 188 после снятия
восьми байт набивки.

Поэтому [`hls.js`](hls.js) собирает поток сам: качает плейлист, идёт по
сегментам, расшифровывает штатным `crypto`, и отдаёт склеенный TS. ffmpeg
остаётся только перепаковщиком:

```
node -> TS -> ffmpeg -f mpegts -i pipe:0 -c:a copy -f mp3 pipe:1 -> MPD
```

Результат на том же треке: 284,08 секунды, 11 364 398 байт, 320 kbps,
44,1 кГц, стерео; полностью декодируется. Сборка заняла 4 секунды, около 70x
реального времени — с запасом для потокового воспроизведения.

Минус остаётся: поток идёт chunked, без `Content-Length`, поэтому
**перемотка внутри трека работать не будет**. Альтернатива — собирать трек
целиком во временный файл (~11 МБ на 284 секунды) и отдавать с
`Content-Length`; тогда перемотка есть ценой пары секунд на старте.

### Прочее, замеченное на живом API

- Токен из `web_token` живёт **~15 минут**, а не 3 часа. Долго живут именно
  cookie, поэтому автообновление обязательно.
- Каталог аккаунта: 5 разделов (Главная, Моя музыка, Обзор, Радио,
  Обновления), 1 микс, плейлисты и 36 недавних треков.
- В выдаче `audio.search` поле `like` приходит как `undefined` — состояние
  сердечка из поиска взять нельзя, только из каталога.

### Пробник

`tools/probe.js` проходит весь путь за один запуск: cookie → токен → каталог →
поиск → ранжированный GET по плейлисту и по mp3-кандидатам, со статусом,
`Content-Type` и размером для каждого.

```bash
npm install
node tools/probe.js "Кино Группа крови"
```

Cookie он берёт из переменных `VK_COOKIE_P` / `VK_REMIXSID` либо из файла
`.vk-cookies.json` в корне (он в `.gitignore`), и нигде их не печатает:

```json
{"p": "...", "remixsid": "..."}
```

Важно: `p` живёт на домене **`login.vk.ru`**, а `remixsid` — на `vk.ru`. В
DevTools это две разные записи в списке слева, и на `vk.ru` никакого `p` нет.
Оба обязательны: с одним `remixsid` обмен на токен отвечает `unauthorized`.

### Лайк и дизлайк

В VK нет отдельного «лайка»: сердечко в плеере — это добавление трека в «Мою
музыку», то есть `audio.add` / `audio.delete`. Поле `like` приходит вместе с
треком, так что состояние сердечка не нужно запрашивать отдельно — в отличие от
Яндекса, где приходится держать кэш лайкнутых id.

Отдельного «не нравится» (как в VK Миксе) в API нет — эндпоинт недокументирован
и в открытых источниках не найден. Пока дизлайк планируется как `audio.delete`
плюс переход на следующий трек — то же поведение, что сделано для Яндекса.

## Установка

Пока не готово к установке. Когда будет — как обычно для самосборных плагинов:

```bash
scp -r vk_music_for_volumio_vl volumio@<ip>:/data/plugins/music_service/vk_music
```

и добавить запись в `/data/configuration/plugins.json`.

## Оговорка

Приватный API формально не предусмотрен правилами VK для сторонних клиентов.
Плагин рассчитан на личное прослушивание собственной библиотеки на своём
устройстве.
